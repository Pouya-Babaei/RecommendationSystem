# Team Guide

## Project 4 --- Recommendation System

### Development Workflow

The project follows a sprint-based, engineering-focused workflow.

For each sprint:

1.  Define the sprint goal and business problem.
2.  Identify research and engineering questions.
3.  Implement the required analysis or functionality.
4.  Review the results and make engineering decisions.
5.  Document key findings and decisions.
6.  Review the sprint before moving to the next stage.
7.  Commit the completed work to Git.

### Documentation

Each sprint should update the relevant documentation when necessary:

-   `reports/sprint_XX.md`
-   `PROJECT_JOURNAL.md`
-   `ENGINEERING_DECISIONS.md`
-   `CHANGELOG.md`

The README should be updated when project-level information or
milestones change.

### Engineering Principles

-   Understand the data before modeling.
-   Do not treat identifiers as meaningful numerical features without
    justification.
-   Prefer decisions supported by evidence from the dataset.
-   Avoid removing data automatically before understanding its meaning.
-   Select visualizations based on the question being investigated.
-   Keep temporal ordering in mind when analyzing interaction data.
-   Document important engineering trade-offs and alternatives.
-   Do not move to modeling before the dataset and validation strategy
    are sufficiently understood.
